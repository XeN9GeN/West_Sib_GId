# Задание ИИ-агенту: справки об объектах Новосибирска

## Цель

Подготовить проверяемые краткие русскоязычные справки для переданного списка
культурных объектов города Новосибирска. Результат будет проверен и затем
импортирован в проект отдельным скриптом. Не подключайтесь к БД и не изменяйте
код проекта.

Обрабатывайте только объекты из входного файла. Не добавляйте новые места и не
ищите другие объекты самостоятельно.

## Контекст проекта

Проект показывает культурные и природные места рядом с Транссибирской
железной дорогой. Исходные данные мест берутся из OSM; описания могут уже
приходить из OSM, Wikidata, Wikipedia или WikiVoyage. Агент получает только
подготовленный список объектов, для которых проекту требуется дополнительная
справка.

Файл создаётся из локальной БД командой из корня проекта:

```powershell
python -B -m scripts.export_novosibirsk_research
```

База данных должна быть запущена и доступна через `DATABASE_URL` (по умолчанию
`localhost:5434`). Команда формирует
`agent_research_novosibirsk/novosibirsk_places_input.jsonl`. Она только читает
БД и не изменяет записи.

Не записывайте результат в поля `short_description` или `history`: они
предназначены для имеющихся описаний и исторических данных из источников.
Результат этого этапа планируется хранить отдельно как `ai_summary` с
собственным списком источников. Поле и импортёр в проекте пока не созданы.

Идентификатор записи в проекте — пара `osm_type` + `osm_id`:

- `osm_type`: `node`, `way` или `relation`;
- `osm_id`: целое число, идентификатор объекта OSM.

Имя не является идентификатором: оно может повторяться, меняться или иметь
варианты написания. Не переименовывайте и не объединяйте объекты.

## Географические границы

- В этой итерации рассматривается только город Новосибирск, а не вся
  Новосибирская область.
- Входной файл уже ограничен проектом; не расширяйте его за счёт соседних
  городов и посёлков (например, Бердска, Оби или Кольцово).
- Для отбора используется полигон городской границы из OSM relation
  `1751445` («городской округ Новосибирск»); он приложен в
  `novosibirsk_city_boundary.geojson`. Координаты места проверяются на
  принадлежность полигону, а не только на попадание в прямоугольник.
- Граница получена 21 ноября 2026 года из OSM relation
  [1751445](https://www.openstreetmap.org/relation/1751445). Данные OSM
  распространяются по лицензии ODbL; атрибуция:
  https://www.openstreetmap.org/copyright.
- Координаты и адресные теги используйте для идентификации места, а не как
  единственное доказательство его истории.
- Если не удаётся надёжно определить, что источник относится именно к
  указанному объекту в Новосибирске, верните статус `ambiguous`.

## Что считать хорошей справкой

- Напишите по-русски 1–3 коротких предложения, максимум 500 символов.
- Излагайте проверяемые сведения о конкретном объекте: назначение,
  архитектурные особенности, историю, значимые даты — только если они
  подтверждаются источниками.
- Перефразируйте своими словами. Не копируйте абзацы из статей и не добавляйте
  оценочных формулировок.
- Не выводите историю или назначение из одного лишь названия, категории,
  координат или общих знаний о городе.
- Не придумывайте факты, даты, архитекторов, статус охраны и связи с
  известными людьми.
- Не создавайте текст ради заполнения поля. Если надёжной информации нет,
  верните `no_reliable_sources` и `summary_ru: null`.
- Не включайте в справку фразы «информация отсутствует», нейтральные подписи
  вроде «Музей», рекламный текст и рекомендации посетителям.

## Источники и проверяемость

Для статуса `ready` приложите не менее одного источника, который подтверждает
содержание справки и относится к конкретному объекту. Для исторических дат и
спорных утверждений предпочтительны два независимых надёжных источника.

Приоритет источников:

1. официальные страницы учреждений, органов власти, музеев и организаций,
   отвечающих за объект;
2. государственные реестры и опубликованные научные/краеведческие материалы;
3. Wikipedia, WikiVoyage и другие справочные издания — как дополнительные
   источники, особенно если они содержат ссылки на первичные материалы.

Для каждого источника укажите полный `https://` URL, заголовок, издателя и
дату обращения. Источник должен вести на страницу с подтверждающей
информацией, а не только на поисковую выдачу или главную страницу сайта.
Не используйте закрытые, недоступные или не относящиеся к объекту страницы.

## Входной файл

После запуска экспортёра владелец проекта передаст файл
`novosibirsk_places_input.jsonl` формата JSON Lines: одна JSON-запись на
строку. Поля записи:

```json
{
  "osm_type": "way",
  "osm_id": 123456789,
  "name": "Пример объекта",
  "type1": "human",
  "type2": "architecture",
  "lat": 55.0000,
  "lon": 82.9000,
  "tags": {
    "historic": "building",
    "start_date": "1900"
  },
  "wikidata_id": "Q12345",
  "existing_sources": [
    "https://www.openstreetmap.org/way/123456789"
  ]
}
```

Это пример формата, а не реальные данные. `tags`, `wikidata_id` и
`existing_sources` могут быть пустыми или отсутствовать. Считайте их подсказками
для поиска; самостоятельно проверяйте факты по источникам. В выборку попадают
объекты без заполненных описания и истории в проекте и без описательных тегов
OSM/Wikidata/Wikipedia/WikiVoyage.

## Формат результата

Верните один файл `novosibirsk_place_research.jsonl` в UTF-8. В нём должна быть
ровно одна JSON-запись на каждую входную запись, в том же порядке. Не
пропускайте объекты без найденной информации. Для каждой строки сохраните
`osm_type` и `osm_id` без изменений.

Формат записи результата:

```json
{
  "schema_version": 1,
  "osm_type": "way",
  "osm_id": 123456789,
  "status": "ready",
  "summary_ru": "Краткая проверяемая справка об объекте.",
  "sources": [
    {
      "url": "https://example.org/object",
      "title": "Страница об объекте",
      "publisher": "Название организации",
      "accessed_at": "2026-11-21"
    }
  ]
}
```

Допустимые статусы:

- `ready` — справка подтверждена источниками; `summary_ru` — непустая строка,
  `sources` содержит подтверждающие ссылки;
- `no_reliable_sources` — подходящая информация не найдена;
  `summary_ru` равен `null`, `sources` пуст;
- `ambiguous` — нельзя уверенно сопоставить источники с объектом;
  `summary_ru` равен `null`; при желании добавьте `note` с краткой причиной.

Не добавляйте поля, не описанные в контракте. Не изменяйте идентификаторы,
статусы и формат дат. Не возвращайте CSV, таблицу Markdown, архив или код
вместо JSONL.

## Самопроверка перед передачей

1. Число строк результата совпадает с числом строк входного файла.
2. Каждая пара `osm_type` + `osm_id` встречается ровно один раз и совпадает с
   соответствующей входной записью.
3. Каждая запись `ready` содержит непустую справку и хотя бы один источник.
4. У `no_reliable_sources` и `ambiguous` значение `summary_ru` равно `null`.
5. Текст не превышает 500 символов, написан по-русски и не содержит
   неподтверждённых фактов.
6. Все JSON-строки корректно разбираются; URL начинаются с `https://`.

Передайте владельцу проекта только файл
`novosibirsk_place_research.jsonl` для последующего размещения в
`scripts/novosibirsk_place_research.jsonl` и отдельно, если необходимо, короткий
список неразрешённых вопросов. Не пытайтесь импортировать результаты в базу.

Файл результата передаётся отдельно от входного файла и этой инструкции.
Владелец проекта проверит его и подготовит импортёр; не изменяйте схему БД и не
создавайте миграции.
